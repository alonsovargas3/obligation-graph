# Wave 4: Query API, MCP Server, UI, `make eval`, README Implementation Plan (rev 1)

> **For agentic workers:** you are a supervised Orca worker. Do only your Task. Tests under `tests/` are frozen (pinned by `tests/FROZEN.sha256`), and so are the coordinator-authored contract files listed under "Contract files". You write implementation code only. Use `ask` for any ambiguity. Send `worker_done` once. You never hold or read an API key, and nothing in your Task calls the network.

**Goal:** CLAUDE.md build steps 9 to 12, plus the Definition of done.
- Agents can ask the graph questions over MCP (stdio) with clauses attached.
- A controller can browse obligations and change orders in one local page.
- `make fetch ingest extract eval` runs clean from a fresh clone and reproduces the committed numbers.
- The README publishes those numbers from committed results files.

**Architecture:**

```
graph.db (visible_* views only)
   └── og.query (read API; the only reader; returns dicts carrying ClauseRefs)
         ├── og.mcp.server   (MCPServer, stdio): list_agreements, get_obligations,
         │                    upcoming_deadlines, check_change_order
         ├── og.ui.server    (stdlib http.server): /api/* JSON + ui/index.html
         └── og.eval all     (make eval): extract + change scores, drops, gates, cost
recorded responses (eval/recorded/, tracked) ──replay──▶ make extract / make change at $0
```

**Tech Stack:** Python 3.12, uv, `mcp` 2.2 (already locked; `from mcp.server.mcpserver import MCPServer`), sqlite3, stdlib `http.server`, pyyaml, pytest, ruff. No new dependencies. The UI is plain HTML, CSS, and JS in one file, with no CDN and no framework.

**Spec:** CLAUDE.md (MCP server, UI, Evaluation, README "Where this goes", Definition of done), ADR-001..009, and the wave 2 and wave 3 reports.

## Global Constraints

- **The invariant at the edge:**
  - `og.query` reads only `visible_obligation`, `visible_supersedes`, `visible_change_finding`, `visible_agreement_party`, `visible_defined_term` and `load_change_report`. No other module issues SQL against obligations, clause refs, or findings.
  - Every obligation, finding, or answer returned by MCP or the UI carries at least one ClauseRef: `{agreement_id, section, page, char_start, char_end, span_text}`.
  - Obligations with status `redacted` or `blank` are returned with `status` and a `marker` (`"[REDACTED]"`, `"[BLANK]"`). Their amount, date, and party fields are null. Nothing is inferred.
- **Read-only surfaces.** MCP and the UI never write to `graph.db` and never call a model. `check_change_order` returns the stored, verified ChangeReport for a pinned change order, in both modes plus a gate summary. For an unknown path it returns a structured error with the pipeline steps to run (`add to data/sources.yaml; make fetch ingest extract change`).
- **Dates.** `upcoming_deadlines` takes `as_of` (ISO date, default today in UTC) and `days` (default 90). It returns obligations whose `effective_due` falls in `[as_of, as_of + days]`, and lists pending ones (no computable due date) separately, never with a guessed date. The corpus dates are 2011 to 2020, so the README demo passes an explicit `as_of`.
- **Reproducibility (new, ADR-010):**
  - Recorded model responses are tracked under `eval/recorded/{extract,change,gate}/`, moved from `data/cache/`. They are the existing allowlisted cache payloads: findings or items plus usage, with no prompts, headers, or keys.
  - The CLIs read and write that directory by default. `--no-cache` still bypasses it.
  - A fresh clone with a key replays every call at $0 incremental cost. Without a key, a full replay still succeeds, because the client is constructed lazily on the first miss.
  - Gate samples get a cache too, keyed by (request fingerprint, sample index), so a gated run replays exactly.
- **Numbers.** README tables are generated by `python -m og.eval readme-tables` from the committed `eval/results/` files. A frozen test checks that the README contains exactly the generated tables. No hand-typed metric.
- **Copy.**
  - No em dashes in the README, UI, or MCP tool descriptions.
  - The README says the corpus "includes a public agreement Fluidstack is party to", with no commentary on any party's commercial position.
  - The README's "Where this goes" section claims no behavior the code lacks.
- **Secrets, tests, tooling:** unchanged from wave 3. Offline tests, `uv run --locked`, never `ruff check --fix`.

## Review Focus

1. **Redacted obligation through MCP:**
   - The Carbonite lease has about 57 `[***]` marks. `get_obligations(type="payment")` returns its redacted rows with `marker: "[REDACTED]"`, a null amount, and the verbatim span.
   - A redacted amount never appears as a number anywhere in the response.
2. **Ungrounded row:** an obligation whose only ClauseRef has `grounded = 0` is absent from every MCP tool, every UI endpoint, and the eval counts, with no caller-side filter.
3. **Superseded filter:**
   - `include_superseded=false` hides obligations whose lifecycle is `superseded`, and `true` shows them with the supersession citation.
   - Zero edges exist in the corpus today, so this is tested on a synthetic graph.
4. **Party question:**
   - "What do we owe the landlord" maps `party="landlord"` to obligations whose `owed_to` party holds role `landlord` in that agreement (`visible_agreement_party`).
   - Names also match, case-insensitively.
   - Obligations with an unresolved payee are excluded and counted in `unresolved_party_count`, never guessed.
5. **Fresh clone:**
   - `git clone`, `uv sync --locked`, then `make fetch ingest extract eval` with a key reproduces `eval/results/` byte-for-byte, apart from the date and run ids, at `incremental_cost_usd == 0`.
   - Without a key, `make extract eval` still succeeds from the recorded responses.

## Contract files (coordinator-authored in B4, frozen)

- **`src/og/query.py`:** signatures and TypedDicts only; bodies are Task 30. The schema of every returned dict is a contract:

```python
class ClauseRefOut(TypedDict): agreement_id: str; section: str | None; page: int | None; char_start: int; char_end: int; span_text: str
class AgreementOut(TypedDict): id: str; title: str; type: str; is_form: bool; base_agreement_id: str | None; filer: str | None; filing_date: str | None; source_url: str; sites: list[dict]; parties: list[dict]; obligation_count: int
class ObligationOut(TypedDict): id: int; agreement_id: str; type: str; status: str; marker: str | None; lifecycle: str; owed_by: dict | None; owed_to: dict | None; description: str; amount: str | None; currency: str | None; due_date: str | None; effective_due: str | None; anchor_event: str | None; offset_days: int | None; trigger: str | None; site: dict | None; clauses: list[ClauseRefOut]; superseded_by: list[dict]
class DeadlinesOut(TypedDict): as_of: str; days: int; window_end: str; scheduled: list[ObligationOut]; pending: list[ObligationOut]; unresolved_party_count: int

def list_agreements(con) -> list[AgreementOut]
def get_obligations(con, *, party=None, site=None, type=None, agreement=None, include_superseded=False, limit=200) -> dict  # {"obligations": [...], "count": int, "truncated": bool, "unresolved_party_count": int}
def upcoming_deadlines(con, *, days=90, party=None, as_of=None) -> DeadlinesOut
def change_order(con, change_order: str) -> dict  # {"change_order_id", "ungated": ChangeReport, "gated": ChangeReport | None, "gate_summary": {...}} or {"error": code, "message": str}
```

- **Sites (schema v4, `user_version = 4`):**
  - `agreement_site(agreement_id, site_id, clause_ref_id NOT NULL)`, with a view `visible_agreement_site` (grounded, same-agreement ref).
  - The `sites:` entries in `data/sources.yaml`, coordinator-pinned per document: `{name, location, segment_id, quote}`. The quote must ground exactly. Examples: "55 Middlesex Turnpike, Bedford, Massachusetts" for the CC lease chain, and "2121 South Price Road, Chandler" for Carbonite.
  - The extraction writer creates `site` and `agreement_site` rows from the verified pin. Obligations inherit the site through their agreement. `obligation.site_id` stays null because extraction does not bind sites.
  - The `site` filter matches site name or location, case-insensitively.
- **`eval/recorded/` layout and `og.replay`:**
  - `og/replay.py` exports `RECORDED_ROOT = Path("eval/recorded")` and `cache_dir(kind) -> Path`, where kind is `extract`, `change`, or `gate`.
  - The gate cache payload is `{answer_text, attempts, stop_reason}`, allowlisted.
- **`prompts/` unchanged.** No prompt or schema edits in wave 4, so replay stays valid.
- **Makefile targets:**
  - `eval: change` then `uv run --locked python -m og.eval all`
  - `mcp: uv run --locked python -m og.mcp`
  - `ui: uv run --locked python -m og.ui` (binds 127.0.0.1:8765)
  - `readme: uv run --locked python -m og.eval readme-tables --check README.md`

## Tasks (workers)

### Task 30: `og.query` read API (TDD; invariant-bearing)

**Files:** `src/og/query.py` (bodies). Tests: `tests/test_query.py`, `tests/test_query_invariant.py`.

- Every function opens no transaction and writes nothing.
- SQL touches only the visible views and contract tables listed above. A frozen test parses `og/query.py` and checks that it never names `FROM obligation`, `FROM clause_ref`, or `FROM change_finding` directly.
- **Party matching:** a role word (`landlord`, `tenant`, `guarantor`, `provider`, `customer`, `lender`) resolves through `visible_agreement_party` within the obligation's agreement. Any other string matches party names case-insensitively.
- **Ordering:** by `effective_due`, then agreement, then id. `limit` caps the list and sets `truncated`.
- **Redacted and blank:** `marker` is set and value fields are null. Covers Review Focus 1, 2, 3, and 4.

### Task 31: MCP server

**Files:** `src/og/mcp/server.py`, `src/og/mcp/__main__.py`. Tests: `tests/test_mcp_server.py`.

- `build_server(db_path) -> MCPServer` registers exactly four tools with typed parameters and descriptions with no em dashes:
  - `list_agreements`
  - `get_obligations(party?, site?, type?, agreement?, include_superseded=false)`
  - `upcoming_deadlines(days=90, party?, as_of?)`
  - `check_change_order(path)`
- **`check_change_order(path)`:** accepts a change-order id, a sources.yaml `local_path`, or a raw filename. Tools return JSON-serializable dicts from `og.query`.
- **Connection:** each call uses a fresh read-only SQLite URI (`file:...?mode=ro`). A missing db returns a structured error ("run make extract").
- **Tests** call `await server.list_tools()` and `await server.call_tool(name, args)` in process (`anyio.run`), plus a stdio subprocess smoke test using `mcp.client.stdio`. Every tool result is checked for ClauseRefs on every returned item.

### Task 32: UI page and local server

**Files:** `ui/index.html`, `src/og/ui/server.py`, `src/og/ui/__main__.py`. Tests: `tests/test_ui_server.py`, `tests/test_ui_page.py`.

**Server:**
- `make_handler(db_path)` serves `GET /` (the page), `/api/agreements`, `/api/obligations?party&site&type&agreement&status&include_superseded`, `/api/deadlines?days&as_of&party`, `/api/change/<id>`.
- It answers only GET and binds 127.0.0.1 only.

**Page:**
- **Left:** an obligations table with filters for party, site, type, and status.
- **Right:** the selected row's clause, verbatim, with agreement, section, and page.
- **Redacted and blank rows:** visibly marked.
- **Change-order view:** a findings list with the old clause and the new clause side by side, plus the gate decisions and the skipped checks.
- No dashboards, no charts, no external URLs, and no inline secrets.

**Tests:**
- Server endpoints return the same dicts as `og.query`.
- Static page checks: no `http(s)://` loads, no em dashes, required element ids present, and a JS-free fallback message.

### Task 33: Recorded-response replay and site pins

**Files:**
- `src/og/replay.py` (body).
- Modify `src/og/extract/__main__.py` and `src/og/change/__main__.py` (the default cache dir comes from `og.replay`).
- `src/og/gates/haiku.py`: an optional `cache` argument. A hit makes no call and is settled as a zero-cost replay.
- `src/og/store/writer.py`: write the site pin.

**Tests:** `tests/test_replay.py`, `tests/test_sites.py`.

**Acceptance:** all wave 1 to 3 tests stay green, and a gated run with a warm gate cache makes zero client calls.

### Task 34: `make eval` aggregator and README table generator

**Files:** `src/og/eval/all.py`, `src/og/eval/readme.py`, `src/og/eval/__main__.py` (subcommands `all` and `readme-tables`). Tests: `tests/test_eval_all.py`, `tests/test_eval_readme.py`.

**`og.eval all`:**
- Scores the extraction reference lease, and the change orders that have reference files.
- Writes `eval/results/<date>.json` with:
  - extraction precision lower bound and recall per type;
  - grounding drops count by reason, from the latest run log;
  - change-order finding precision and recall;
  - gate recall and precision per backend, against the reference and against the ungated run;
  - cost and latency, gated vs ungated.
- Prints those same sections as plain tables.

**`readme-tables`:** renders the markdown tables from a results file. `--check README.md` exits non-zero if the README's generated blocks (between `<!-- og:tables:start -->` and `<!-- og:tables:end -->`) differ.
